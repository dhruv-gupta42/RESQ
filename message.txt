The problem we're solving is:

When multiple emergencies occur, it can be difficult for a person monitoring them to keep track of all incidents, their severity, locations, and current response status in one place.

RESQ gives the user a single emergency-response dashboard where they can simulate and manage incidents.

Example situation

Imagine you're operating a fictional emergency control room.

You receive:

🔥 Fire
Location: Andheri
Severity: Critical

🚑 Medical Emergency
Location: Bandra
Severity: High

🚗 Accident
Location: Dadar
Severity: Medium

Instead of having these as random notifications, RESQ puts everything into one organized interface.

2. Create an Emergency

There is a form:

Create Emergency

Emergency Type
[ Fire ▼ ]

When you click the button, JavaScript creates a new emergency card.

3. Emergency Cards

Each emergency can look like:

┌──────────────────────────────┐
│ 🔥 FIRE                      │
│                              │
│ 📍 Andheri                   │
│ ⚠ Critical                  │
│ 🕐 10:42 PM                  │
│                              │
│ Status: ACTIVE               │
│                              │
│ [ RESPOND ]   [ RESOLVE ]    │
└──────────────────────────────┘

Everything is dynamically generated with JavaScript.

🚑 4. Response Status

This is where the site becomes more interactive.

An emergency can go through:

ACTIVE
   ↓
RESPONDING
   ↓
RESOLVED

For example:

🔥 Fire — Andheri

Status: ACTIVE

        ↓ Click Respond

Status: RESPONDING

        ↓ Click Resolve

Status: RESOLVED

The dashboard counters update automatically.

📊 5. Dashboard Statistics

JavaScript can calculate:

Active Emergencies     7
Critical Emergencies  2
Responding            3
Resolved              18

So when you create or resolve an emergency, these numbers change automatically.
